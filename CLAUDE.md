# CLAUDE.md

Guidance for Claude Code (and any other agent) working in this Life OS workspace.

## First: is this workspace set up?

If `USER.md` does not exist, the workspace is a fresh clone. Run the `/onboarding` skill
before doing anything else. See `BOOTSTRAP.md`.

## Who you are

Personality, name, and conventions live in the identity files. Read them when relevant:

- `IDENTITY.md` — agent name, vibe (generated by onboarding)
- `SOUL.md` — values and disposition
- `AGENTS.md` — workspace conventions, memory rules, group-chat behaviour, heartbeats
- `USER.md` — who you are serving and how to route between household members
- `MEMORY.md` — long-term memory index (main session only)
- `HEARTBEAT.md` — the checklist run on each heartbeat
- `memory/` — daily logs, operating rules, and job state files

## Directory map

- `.claude/skills/` — skills (also exposed as `skills/` for OpenClaw)
- `context-library/personal/<name>/` — one folder per household member
- `context-library/shared/` — household, Fair Play assignments, budget targets
- `outputs/` — where generated files go (`outputs/daily-plans/` etc.)
- `automations/` — cron and launchd templates, rendered by onboarding
- `setup/` — templates and integration guides
- `templates/`, `sub-agents/`, `advanced/`, `agents/` — empty slots for your own material

## Skills

**Daily life**
- `/daily-plan` — morning plan: calendar, Fair Play duties, chores, budget pulse
- `/fairplay-reshuffle` — renegotiate household responsibilities
- `/schedule` — create reminders and recurring jobs

**Background jobs (run from heartbeat or cron)**
- `date-scanner`, `social-commitment-scanner` — catch plans that never reached the calendar
- `follow-up-chaser` — emails still waiting on a reply
- `birthday-text-drafter`, `relationship-maintenance` — keep up with people
- `travel-prep`, `travel-itinerary-builder` — trip briefs and itinerary docs
- `whatsapp-calendar` — react to a message to add it to the calendar
- `budget-autocategorize` — tidy uncategorised transactions
- `system-health` — auth, disk, and session checks

**Setup**
- `/onboarding` — first-run interview; safe to re-run to change answers

## How to work

- **Read state, not history.** For "did this job run today?", read the state file in
  `memory/`. Never trust earlier conversation turns.
- **Single source of truth.** Names, accounts, and chat IDs live in `USER.md` and
  `context-library/`. Skills look them up there. Do not hard-code them into skills.
- **Outputs go in `outputs/<type>/`.**
- **Ask before sending.** Anything that leaves the machine on the user's behalf needs
  explicit approval unless a rule in `memory/` says otherwise.
- **Never commit personal files.** `.gitignore` covers them. Do not weaken it.

## Voice

Direct. Short over long. Sound human. Specific over generic. No filler, no hedging.
The user's own preferences in `context-library/personal/<name>/` override this.
